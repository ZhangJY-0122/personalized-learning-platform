# 成员 3：个性化学习推荐系统最终整体方案

版本：V2.0（独立交付与需求评审版）  
评审日期：2026-09-09  
对应题目：F21  
项目名称：基于知识追踪与混合推荐算法的个性化学习推荐系统  
当前目标：独立开发、独立启动、独立演示、独立提交代码与报告。

本版依据用户最新要求，以本项目自带的账号、课程、资源、题目和学习行为完成全部核心流程。无需启动其他成员服务，也无需等待外部数据或接口。总体架构、需求范围、算法口径和验收标准以本文件为本项目的实施基线；原团队接口仅作为未来适配参考。

V1.1 已保存在[归档原稿](archive/05-成员3-个性化推荐与算法方案-V1.1.md)。本次需求评审的问题、处置和剩余风险见[需求评审与风险记录](06-成员3-需求评审与风险记录.md)。

## 1. 可行性结论与范围

### 1.1 评审结论

技术上可行，采用单个 Spring Boot 业务服务、MySQL、Vue 和一个可选在线使用的 FastAPI 推理服务，复杂度可以控制在个人课程设计范围内。

交付安排为“先完成工程闭环，再完成研究实验”。BKT、规则推荐和路径规划在 Java 本地运行，断开 Python 服务也能继续作答并更新结果。DKT 的训练和真实对比实验是最终研究交付要求；DKT 在线启用属于增强能力，不是业务系统启动前提。

从零开发全部功能并完成三组随机种子实验，一周内交付风险高。本方案以 10～14 个有效工作日作为计划假设，不作为工期保证；第 7 天目标是可独立演示的核心版本。实际进度以第 12 节关卡通过为准。若只有 7 天，先交付核心版本并明确列出未完成研究项，不能把核心版本称为完整研究成果。

本次完成的是设计与需求评审，不代表代码已实现、模型已训练、性能已达标。

### 1.2 三个交付层级

| 层级 | 内容 | 验收定位 |
|---|---|---|
| M0 核心独立版 | 登录、初始化/导入、练习、事件处理、画像、规则/BKT、薄弱点、混合推荐、反馈、动态路径、断网启动 | 第一阶段必须通过 |
| M1 最终研究版 | 规则/BKT/DKT预测对比、推荐策略对比、模型/实验看板、教师课程统计、三门演示课程、报告和测试 | 最终提交必须通过 |
| M2 可选增强 | DKT在线排序、复杂协同过滤、班级管理、SAKT、多课程迁移、外部平台集成 | 不阻塞M0/M1 |

推荐实验中保留一个简单 Item-CF 基线，属于 M1 研究工作；复杂在线协同过滤属于 M2。这样既能做原定策略对比，又不把它设为主链路依赖。

### 1.3 明确不做

- 完整教学平台：排课、选课审批、正式考试、正式成绩台账和排名。
- 完整错题本：笔记、教师批改、复习工作流。
- 大模型问答、聊天助教、自动生成解释。
- 在线训练、Kafka、Kubernetes、服务注册中心。
- 真实班级同步、跨服务JWT和BFF实现。

本项目需要的简化账号、客观题练习和样例课程由自己提供，属于独立演示能力；不将这些模块扩展为另一个教学考试系统。

### 2.1 认证与数据边界

- `APP_MODE=standalone` 为唯一默认模式。本地 `local_user` 存演示账号密码哈希，登录签发本地 JWT。
- 服务端校验签名、有效期和固定的本地 issuer/audience；JWT密钥从环境变量注入，不硬编码生产秘密。
- 学生的userId从JWT读取；URL中的userId必须匹配本人。教师权限由本地 `teacher_course_scope` 确认，不仅校验role。
- 初始化样例账号和教师课程授权，不建设复杂组织机构；班级统计当前改为课程统计。
- 批量事件导入、补偿、模型注册只允许管理员；学生只能通过练习/资源行为API触发事件。
- 不导入真实个人资料。所有业务ID由独立数据工厂生成UUID；如以后接入外部系统，再通过适配器切换ID来源。

### 2.2 独立学习闭环

学生登录 → 查看课程及画像 → 推荐基础内容 → 阅读资源 → 完成练习 → 服务端判分 → 本地事件 → 更新BKT → 更新薄弱点 → 推荐与路径刷新。

管理员另有“导入模拟行为”入口，用于复现历史和故障测试。学生练习不允许直接上传 `correct=true` 冒充判分结果。两条入口均进入同一个事件处理器。

## 3. 最终开发架构

```text
Vue 3 :5173
    │ HTTP /api/v1
Spring Boot :8083（单实例）
    ├─ 本地认证、课程数据、资源和练习
    ├─ 事件入库、事务、重试、画像
    ├─ Java规则/BKT、推荐排序、DAG路径
    ├─ 实验查询、模型路由
    │
    ├─ MySQL :3306 / recommender_db
    ├─ 本地资源和模型目录 artifacts/
    └─ FastAPI :8001（M1加载DKT，M2按需在线预测）
            └─ 指定课程模型、知识点映射

training/ 离线清洗 → 规则/BKT/DKT评估
                   → 模型文件、指标JSON、数据清单
                   → 注册到本地系统
```

沿用 Java 17、Spring Boot 3、Vue 3/Vite/Pinia、MySQL 8、Python 3.11/PyTorch/FastAPI 的技术路线。具体小版本在建项目时验证兼容并锁定于构建文件和锁文件，不在方案中声称某版本为最新。

### 3.1 职责决策

- Spring Boot拥有所有业务写入，Java实现在线BKT和规则基线、推荐及路径，不依赖FastAPI完成事务。
- Python实现离线训练评估和DKT推理；Python/Java BKT使用同一参数文件与测试向量，避免两种结果不一致。
- DKT不覆盖BKT潜在掌握状态。可在线提供答对概率用于难度排序；BKT持续更新，保证DKT退出后没有历史断层。
- FastAPI无业务数据库写权限，不暴露给浏览器；只绑定本机/容器内部网络。
- HTTP推理发生在数据库事务之外；结果携带输入状态版本，过期结果丢弃。
- 初始只运行一个业务实例和一个数据库事件工作器。多实例消费不是当前交付目标。

## 4. 自带数据与Mock策略

### 4.1 无外部依赖的数据包

首个可运行版本用“Java程序设计”一门课：3章、8～12个知识点、至少12个本地资源、40道客观题、30名模拟学生、约2000条行为。每个进入路径的知识点至少配置资源、基础题、进阶题和一组复测题；内容缺口在导入时报告。

M1扩展为Java、数据结构、计算机网络三门课，每门15～20个知识点、20个资源、60～80道题、30～50名学生，总计约6000～10000条行为。无需建立试卷/正式考试模块。

- 内置Markdown/HTML安全渲染的资源正文，不依赖外链视频或下载才能演示。
- UUID采用固定种子数据清单，重复初始化保持引用稳定；新增实体生成新UUID。
- 数据生成器模拟不同初始能力、学习速度、猜测/失误和资源偏好，输出可复现事件。
- 不为展示提升而手动修改掌握度或实验指标。答对不保证每种模型每次均上涨，展示真实计算。
- 缺少难度默认0.5且标注来源；难度统一0～1，越大越难。没有真实用时则为null，不造时间。
- 先修边含义固定为source是target的先修。禁止自环、跨课程边、悬空引用和环路。

### 4.2 导入

首版支持一个目录JSON包和一个事件CSV模板；文件大小上限10MiB、事件每文件最多10000条，超出提示拆分。

目录包全量校验通过后原子发布；错误包不部分激活。事件按行校验并返回成功/失败明细，正确行经过正常消费者处理。保存文件哈希、行号、作业ID和错误文件；同文件重传返回原作业。事件的稳定eventId使重新导入不重复学习。

Mock提供的是数据和本地可信行为源，画像、BKT、推荐分数和路径必须真实计算，不能将接口全部返回硬编码结果。

### 4.3 公开实验数据

ASSISTments 2009–2010修正版用于研究对比，下载是研究增强步骤，不阻塞M0运行。官方说明修正版将多技能题合并为一行，不能把该行再当成多次独立作答。[ASSISTments官方数据说明](https://sites.google.com/site/assistmentsdata/home/2009-2010-assistment-data/skill-builder-data-2009-2010)

记录数据版本、下载来源、文件哈希和清洗统计。原始下载如未成功，先用合成数据跑通同一训练管线，实验页明确标“SYNTHETIC_DEMO”；不得冒充已完成公开数据实验。Junyi、EdNet不纳入当前必做范围。

外部ID保存在独立映射中；公开数据使用独立实验课程/知识点空间，不能直接映射成Java知识点。模型仅供其对应空间使用。再分发原始数据前检查来源许可；可先交付下载说明、清洗代码、哈希和符合许可的产物。

### 5.1 表与约束

| practice_submission | submissionId、userId、questionId、answer、correct、catalogVersion、idempotencyKey、payloadHash | 服务端判分；用户+幂等键唯一 |
| learning_interaction | interactionId、sourceEventId、sourceService、eventSeq、eventType、userId、courseId、itemId、correct、durationMs、occurredAt、catalogVersion | sourceEventId唯一；原始标准化行为不改写 |
| interaction_knowledge | interactionId、knowledgeId、normalizedWeight | 交互+知识点唯一；保留当时关联 |
| event_consume_log | eventId、sourceService、payloadJson、payloadHash、status、retryCount、nextRetryAt、error、consumedAt | eventId唯一，另保留契约要求的eventId+sourceService唯一 |
| student_profile | userId、courseId、accuracy、activityDays、medianDurationMs、preference、featureVersion | 用户+课程唯一 |
| learner_course_state | userId、courseId、catalogVersion、stateRevision、lastOrderKey、status | 用户+课程唯一；事务串行锁点 |
| mastery_state | userId、courseId、knowledgeId、modelName、modelVersion、catalogVersion、mastery、evidenceCount、evidenceWeight、version | 保留用户+课程+知识点+modelVersion唯一 |
| mastery_history | triggerEventId、knowledgeId、beforeMastery、afterMastery、modelVersion、replayGeneration、createdAt | 事件+知识点+模型+重放代唯一 |

| recommendation_batch/item | batchId、stateRevision、catalogVersion、strategyVersion、modelVersion、status、expiresAt；项目分数/解释 | 批次+itemType+itemId唯一 |
| recommendation_feedback | feedbackId、recommendationId、userId、type、idempotencyKey、payloadHash、sourceEventId、occurredAt | 用户+幂等键唯一；可信完成按项目+sourceEventId唯一 |
| learning_path/node | pathId、pathVersion、stateRevision、catalogVersion、status、reason；sequenceNo、itemId、nodeStatus | 用户课程+pathVersion唯一；路径+sequenceNo唯一 |
| model_registry、experiment_run | 课程/目录/数据/特征版本、映射、参数、seed、metrics、artifactPath、checksum、status | 模型名+版本+课程+目录唯一 |
| import_job/import_error、replay_job、idempotency_record | 来源、请求哈希、状态、计数和错误 | 导入、重放、命令重试可追溯 |
| external_id_map | datasetVersion、entityType、externalId、internalId | 前三项联合唯一 |

查询索引覆盖用户+课程+时间、课程+知识点、事件状态+nextRetryAt和批次创建时间。索引及外键在schema.sql落地，不能只停留在报告中。

### 5.2 版本规则

- modelVersion使用全局不重用的标识，例如bkt-java-cat1-param1；更换目录或参数产生新版本，避免原唯一键混淆目录。
- catalogVersion变化后校验并原子切换快照，旧模型/推荐/路径停止作为当前有效结果展示。
- BKT新版本从对应目录可用历史重建；初版可整课重建，不能直接拿DKT概率当BKT先验。
- 新知识点从默认先验开始；无法映射的旧行为保留历史并报告，不擅自按名称匹配。
- 每次有效学习状态提交递增stateRevision。推荐、路径和DKT结果绑定该revision，旧结果不得伪装最新。
- 资源偏好、内容状态等会改变推荐输入的更新也递增stateRevision；只有查看/获取结果不产生新revision。首次生成推荐先确保对应BKT/画像查询状态已就绪。
- 推荐默认30分钟过期，学习状态或目录变化立即失效；保留历史批次和已产生反馈。

## 6. 学习事件、事务与恢复

### 6.1 事件对状态的影响

| 事件 | 处理 | 是否更新BKT |
|---|---|---|
| QUESTION_ANSWERED | 记录作答、画像、BKT、历史、状态版本 | 是，只依据服务端correct |
| RESOURCE_VIEWED | 记录浏览/偏好 | 否 |
| RESOURCE_COMPLETED | 更新资源节点完成、完成去重和偏好 | 否，阅读不等于已掌握 |
| COURSE_ENROLLED | 本地课程关联/画像初始化 | 否 |
| EXAM_SUBMITTED | 仅作为可导入摘要保存 | 否，避免与逐题事件重复计算 |
| 推荐曝光/点击/主观反馈 | 本地feedback表 | 否 |

本地生产者使用sourceService=local-practice；eventSeq由本项目事件表生成，仅用于本地队列，不冒充外部序号。同一eventId不同内容或来源返回CONFLICT。

事件包沿用schemaVersion=1、batchId、events；每事件至少包含eventId、eventType、userId、courseId、objectType/objectId、occurredAt、sourceService、traceId。答题额外包含correct、knowledgeItems及本地catalogVersion；CSV未提供eventSeq时由本地入库生成。score和durationMs按类型校验，非答题不要求correct。

事件状态为PENDING/SUCCEEDED/FAILED/PENDING_COMPENSATION/NEEDS_ATTENTION；单实例工作器使用事务行锁领取事件，避免持久化PROCESSING后崩溃而永远卡住。用户课程状态为READY/REBUILD_REQUIRED/REBUILDING/NEEDS_ATTENTION；重建作业另存进度和错误。

### 6.2 正常提交

1. 事务A：校验幂等键和请求哈希，服务端判分，保存practice_submission和PENDING事件，一起提交。返回判分和eventId、processingStatus。
2. 本地工作器读取事件；单事件事务B中锁定learner_course_state，重新检查eventId、目录及状态。
3. 事务B同时写learning_interaction、知识点关联、画像、Java BKT状态/历史、路径节点证据、stateRevision、旧推荐/路径失效及SUCCEEDED。
4. 提交后再触发推荐/路径更新任务。Python预测不放在事务B中。
5. 事务B失败全部回滚，在单独短事务记录FAILED和下次重试时间。进程崩溃后仍可从PENDING/FAILED恢复。

重复成功事件不重新计算；未成功事件不能仅因日志行存在就报告重复成功。本地练习判分即时返回，界面在事件处理完成后刷新结果，默认每秒轮询一次，最多10秒后提示处理中。

### 6.3 批量导入与乱序

- 每批最多500条；保存原payload和校验结果。只有已经应用的事件进入acceptedEventIds；已成功重复的进入duplicateEventIds；待补偿/失败的进入failedEvents。
- 顺序键固定为(occurredAt, eventSeq, eventId)。没有真实时间的实验数据使用数据源提供的顺序字段，标记为序列索引，不能伪造真实时间。
- 正常单实例本地事件按序消费；批量历史导入先排序。发现事件早于已应用顺序键时，将该用户课程置REBUILD_REQUIRED并保留待应用事件。
- 管理员重建命令锁定该用户课程，使用已保存事件及待补入事件按序重算画像/BKT到暂存结果，成功后原子替换派生状态，递增replayGeneration和stateRevision。
- 重建期间新事件排队，查询标记REBUILDING；失败保留原结果并标stale，可重试。原始提交、事件、反馈不重复产生。
- 缺实体进入PENDING_COMPENSATION；先补目录再触发排序重建，不能把旧事件直接追加到新状态末尾。
- 仅补齐引用缺失时沿用该事件记录的目录版本；真正变更目录时按5.2新建版本重建，不能以新题目关联悄悄改写旧交互语义。
- 自动重试间隔5、15、60、300、900秒，5次仍失败进入NEEDS_ATTENTION；保留数据并支持管理员重试。
- 当前无跨服务游标；未来适配时再处理源游标与持久化重试队列的一致性。

## 7. 算法口径与确定性实现

所有下述默认阈值均为本项目可配置工程假设，不是已证明最优参数；随strategyVersion保存。

### 7.1 规则与BKT

规则基线采用最近20次有效作答的加权正确率，带平滑：
`p=(1+Σw×correct)/(2+Σw)`；无证据为0.5并标UNKNOWN。

BKT初始演示参数L0=0.2、T=0.1、G=0.2、S=0.1；正式实验仅使用训练集拟合参数。G+S必须小于1，计算概率截断到[1e-6,1-1e-6]。

最小拟合实现为固定种子的受约束随机搜索，以训练集逐步预测LogLoss最小选择参数：L0在[0.01,0.99]、T在[0.001,0.3]、G/S在[0.01,0.4]，每个拟合单元最多100组候选，包含默认参数。知识点训练作答少于100条时使用训练集课程共享参数；公开实验采用主技能协议拟合，演示多技能插值单独验证。

```text
作答前知识掌握概率为 L
预测答对概率 p = L×(1-S) + (1-L)×G
答对后后验 q = L×(1-S) / p
答错后后验 q = L×S / (1-p)
单知识点更新 Lnext = q + (1-q)×T
```

多知识点题：先合并重复知识点，对正权重归一化得到w；全零、负值、空知识点拒绝进入KT。使用项目启发式更新
`Lnext=L+w×((q+(1-q)×T)-L)`。它在w=1时等于标准单技能更新，多技能权重插值不宣称为标准BKT理论结果。保存更新前后值及w以便复算。

### 7.2 BKT与DKT不混用语义

BKT的mastery为潜在掌握估计；DKT给出下一次相关技能作答正确概率。两者不在同一条曲线上无标识拼接，也不用同一个0.6阈值直接切换。DKT输出定义可参见[原论文第3节](https://proceedings.neurips.cc/paper_files/paper/2015/file/bac9162b47c56fc8a4d2a519803d51b3-Paper.pdf)。

业务薄弱点和路径始终使用BKT。模型对比使用“作答前答对概率”，BKT也先转换成p再计算指标。DKT在实验页单独显示，M2启用后仅增强题目难度排序。

### 7.3 DKT最小实现

- 单层LSTM、hiddenSize=64、batchSize=32、学习率0.001，最多20轮，验证LogLoss连续3轮不改善则早停；固定3个随机种子。参数是起点，可在验证集调整。
- 输入为知识点+正确性编码，输出下一步技能概率；用t时刻历史预测t+1，不能将目标答案输入再评估同一目标。
- 多技能题选最高权重技能；并列按固定映射顺序选择。公开数据没有权重时均分后固定选择，并记录丢弃次级技能信息的局限。
- 首版窗口100；只对窗口内有历史的目标计损失，padding屏蔽。第一条无历史样本使用共同冷启动规则，不进入模型比较指标。
- 训练与在线使用相同窗口策略、映射和特征版本；不可在训练中重置状态却在线无限累计。
- 模型绑定课程/目录/映射；公开实验模型不得用于演示Java课程。没有匹配模型时继续Java BKT，系统不报整体故障。

### 7.4 画像与证据

- accuracy只计算有效QUESTION_ANSWERED；用时统计取合法durationMs的中位数，缺失不按0计算。
- 活跃度显示近7日活跃天数0～7；不将其包装成通用学习能力。
- 资源偏好取近30日可信浏览/完成记录的类型占比；没有记录则不启用该推荐分量。
- evidenceCount为相关唯一作答次数，evidenceWeight为归一化w累计。
- evidenceCount<3或evidenceWeight<2标INSUFFICIENT；不因低先验断言薄弱。
- confidence字段若保留，仅为min(1,evidenceWeight/10)的证据充足度指数，界面注明不是统计置信概率。
- 证据足够且BKT<0.6标WEAK，否则ADEQUATE。边界值0.6不算薄弱。
- weakness=0.6×(1-L)+0.2×近20次加权错误率+0.1×importance+0.1×prerequisiteImpact。
- importance无人工标注用0.5并记录默认来源；prerequisiteImpact=可达后继数/max(1,课程知识点数-1)。薄弱列表按weakness降序，平分按UUID。
- 新用户优先基础知识点和入门练习，状态显示待诊断；没有热门行为时按课程顺序回退，不能称为“热门”。

## 8. 推荐、反馈与路径

### 8.1 候选与评分

先选前3～5个有证据薄弱点，补入未达标先修点。过滤下架、跨课程、缺关联和先修不满足的内容；已完成资源7天内默认不重复推荐，仍薄弱时7天后允许复习。习题排除近3次相同题目，必要时放宽并标复习。

四项基线：0.45薄弱匹配+0.25难度匹配+0.20内容匹配+0.10偏好匹配。

| 分量 | 可执行定义 |
|---|---|
| 薄弱匹配 | Σ内容知识点权重×目标知识点weakness，无目标关联为0 |
| 难度匹配 | 有技能答对概率时d=1-min(1,abs(p-0.65)/0.65)；资源或缺预测题用max(0,1-abs(difficulty-加权BKT))启发式 |
| 内容匹配 | 候选知识点权重向量与目标知识点向量的余弦相似度，零向量不启用 |
| 偏好匹配 | 对资源用对应类型偏好占比；无偏好或习题场景不启用 |

p使用作答前BKT预测的知识点加权平均；匹配且有效的DKT可替代该项。技能级概率不能声称为精确的每道题难度预测，同技能题用标注difficulty及稳定ID打破平分。

缺失分量剔除后归一化。前20候选贪心选前5，尽量限制同主知识点最多2条、混合请求至少含一条资源和一道题；不足时先放宽多样性，不放宽跨课程、下架或先修过滤。返回短列表及原因。

解释至少两条来自快照事实、目标关联、难度来源、证据量或先修关系；冷启动可解释“尚无作答证据”和“本内容属于基础知识”，不得编造错误次数。保存reasonJson、scoreDetailJson、策略版本、输入revision和来源。

### 8.2 生成、反馈与有效完成

- GET recommendations只读取当前批次；没有批次返回空items和生成提示，不在GET中无限创建历史。
- 本地POST generate生成并持久化批次，带幂等键；计算后提交前再次校验stateRevision/目录，过期则重算一次或返回CONFLICT。
- EXPOSED在卡片实际显示后记录，CLICKED在打开后记录；以用户+请求幂等键防重试，同键不同内容409。
- 用户点击“已完成”仅作为自报反馈，不计为可信完成，也不更新BKT。
- 习题可信完成来自服务端QUESTION_ANSWERED；资源完成来自本地资源完成API，只改变资源进度。可信行为可以同时写反馈关联和学习事件，但只由学习事件更新KT。
- 优先由练习请求携带recommendationId或pathNodeId，校验该内容/用户匹配，再把sourceEventId关联到项目；没有ID的普通练习只更新知识状态，不任意归因给某个推荐批次。
- helpful/notHelpful每用户每推荐保留最新态及历史。ignored由显式反馈记录，不能把未曝光内容当忽略。
- 推荐失效后仍可接收该历史批次的真实反馈，但不会将其重新激活。

### 8.3 路径

目标知识点及未达标先修点组成DAG，稳定拓扑排序；每点依次安排资源、基础题、进阶题、复测。不同知识点可复用关联内容，但同一路径重复题目应去重并说明。

节点状态PENDING/IN_PROGRESS/COMPLETED/SKIPPED；路径ACTIVE/COMPLETED/INVALIDATED/BLOCKED。资源完成不自动认定技能掌握。复测完成且证据充分、BKT>=0.6才通过该知识点。

失败复测推荐新的补充内容和另一复测题；最多自动安排2轮，仍未达标显示NEEDS_REVIEW，避免无限生成路径。题库不足则BLOCKED并列出缺项。所有知识点已达标可返回COMPLETED空路径。

知识状态提交后令旧路径失效；已开启路径的用户由本地工作任务合并短时间更新后生成新版本。新版本保留已完成且仍有效的内容证据，只重排未完成部分。任务失败提供重试按钮，旧路径可回看并显示stale，不能继续当当前路径使用。

## 9. 实验与报告可信度

### 9.1 知识追踪实验

规则/BKT/DKT必做，按每名学生时间序列70%训练、10%验证、20%测试。短序列无法三分的单独统计，不静默丢弃。先分割再切窗口；不得把同一目标放入多个分区。

主对比中三种方法使用相同的主技能映射、相同有效目标集合和窗口上下文；多技能BKT作为单列扩展，避免把不同输入协议的结果直接当公平对比。数据源仅有序号时报告“顺序切分”，不声称有真实时间戳。

参数估计、归一化、内容统计和调参只用训练/验证对应范围；测试只做最终评估。预处理拟合不得看到测试数据，这是[scikit-learn官方泄漏防范建议](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)强调的原则。

验证/测试按“先预测当前答案，再揭示答案更新历史”逐步推进，允许使用过去已揭示的行为作为下一次输入，但不更新全局模型参数。同一学生在训练和测试出现，是已有学生未来行为预测，报告不声称评估新学生泛化。未知技能使用共同回退并单列覆盖率。

报告AUC、Accuracy（阈值0.5）、RMSE、LogLoss、有效样本数、未知技能率和3次种子均值/标准差。AUC只在同时存在正负样本时计算，否则null并解释；LogLoss截断概率。确定性规则相同结果标准差为0正常。

### 9.2 推荐实验

对比热门、内容、简单Item-CF、不含KT混合、KT混合。内容表示先用知识点向量；Item-CF使用训练时段学生-内容可信完成二元矩阵和余弦相似度；行为不足回退热门并报告回退比例。

固定相同测试用户、时间切点、候选集和过滤规则；排序时不能看到未来行为。相关项定义为测试窗口中的可信完成项目，习题完成指已提交练习，不能把“答对”当唯一兴趣标签。资源和习题分别报告，不能用ASSISTments作答日志虚构资源点击。

Precision@5=命中/5；Recall@5=命中/相关项数；NDCG@5使用二元相关性；没有相关项的用户不计Recall/NDCG并报告数量。短列表保留Precision分母5并报告比例。Coverage为被推荐不同项目数/测试可用项目数；Diversity为列表内知识点向量两两(1-余弦)均值，少于2项为null。

离线完成预测只说明对日志行为的匹配，不证明学习提升。合成数据结果只能用于流程验证和消融；生成器不得根据待比较算法的得分直接生成“正确推荐”标签。

在线看板按选定7日/30日批次窗口统计独立(userId,recommendationId)曝光、点击、可信完成，CTR=点击且曝光数/曝光数、完成率=可信完成且曝光数/曝光数；分母0返回null，未曝光行为单列。没有做真实对照实验时不写“学习效果显著提升”。

- 查询P95<=500ms，本地练习判分响应P95<=500ms。
- 单事件Java BKT处理P95<=300ms；本地提交到前端可见状态P95<=2秒。
- 单次本地推荐生成P95<=2秒；无外部同步5秒轮询延迟。
- FastAPI连接/读取总预算1秒，无请求内连续重试；连续3次失败暂停在线调用30秒，始终可返回Java基线。
- 500条导入允许异步处理，20秒内完成为目标；明确区分上传耗时与全部消费耗时。
- 重建最多10000条演示行为，30秒内完成为目标；超时保留作业状态，不假报成功。
