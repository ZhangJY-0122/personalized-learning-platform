# AI 驱动的个性化学习平台总体设计与集成方案

版本：V1.0  
适用范围：A13、E12、F21 三个个人项目及 F13 综合项目  
开发周期：两周

## 1. 文档定位

本文档只说明总体目标、系统边界、集成架构、两周计划和最终验收方式。具体字段、接口、事件和鉴权规则见《02-统一数据与接口契约》；三位成员的个人开发与交付要求分别见对应成员文档。

五份文档共同构成项目开发基线：

1. 《01-项目总体设计与集成方案》
2. 《02-统一数据与接口契约》
3. 《03-成员1-教学考试系统交接清单》
4. 《04-成员2-成绩学档系统交接清单》
5. 《05-成员3-个性化推荐与算法方案》

## 2. 选题与成果结构

### 2.1 个人项目

- 成员 1：基于 Spring Boot 与 Vue 的在线教育与考试管理平台（A13）
- 成员 2：基于 Spring Boot 与 Vue 的学生成绩及学习档案管理系统（E12）
- 成员 3：基于知识追踪与混合推荐算法的个性化学习推荐系统（F21）

三个个人项目均须具有独立前端、后端、数据库、初始化数据、测试材料和使用说明，能够独立运行、独立演示和独立撰写报告。

### 2.2 综合项目

- 综合项目：AI 驱动的个性化学习平台（F13）

综合项目建立在三个个人项目已经完成的基础上，通过统一登录、统一导航、统一前端、接口聚合和数据事件同步形成完整平台。综合项目不替代三个个人项目。

## 3. 总体原则

1. 先独立完成，再进行集成。
2. 每类业务数据只能有一个主数据负责人。
3. 三个服务拥有独立数据库，不跨库查询或修改。
4. 跨系统实体统一使用 UUID。
5. 系统间只通过版本化 API 和事件通信。
6. 综合项目使用一套登录、一套导航和一套界面。
7. 第二周以适配和集成为主，不全面重写成员代码。
8. 公开数据实验与合成演示数据必须明确区分。
9. 在线推理使用提前训练好的模型，不在演示现场训练。
10. 两周内不引入 Kafka、Kubernetes、服务注册中心或其他非必要基础设施。

## 5. 服务职责与数据所有权

### 5.1 成员 1：教学考试服务

主数据：

- 用户、角色和登录身份
- 课程、章节、知识点目录
- 知识点先修关系的实际课程数据
- 学习资源、题目和试卷
- 学生选课关系
- 原始答题记录
- 考试提交和即时判分结果
- 原始学习行为事件

### 5.2 成员 2：成绩与学习档案服务

主数据：

- 正式成绩台账
- 成绩修改记录
- 班级和课程成绩统计
- 学习档案
- 错题本状态和错题笔记
- 数据导入导出任务

成员 2 不重新判定考试答案，只接收成员 1 的考试结果和答题事件。

### 5.3 成员 3：个性化服务

主数据：

- 算法学生画像
- 知识掌握度及历史
- 薄弱知识点
- 推荐批次、推荐项目和反馈
- 个性化学习路径
- 模型版本和实验记录

成员 3 不保存密码或完整个人资料，只使用算法需要的用户、课程、知识点和行为标识。

## 6. 冲突功能边界

| 容易冲突的功能 | 边界规定 |
|---|---|
| 学习记录 | 成员 1 保存原始行为；成员 2 保存归档和统计结果 |
| 成绩 | 成员 1 负责即时判分；成员 2 负责正式成绩、排名、修改留痕和导出 |
| 错题 | 成员 1 保存原始答案；成员 2 管理错题状态、复习和笔记 |
| 学生画像 | 成员 2 保存正式学习档案；成员 3 保存算法能力、偏好和活跃度特征 |
| 课程目录 | 成员 1 保存主数据；成员 2、3 保存只读快照，不反向修改 |
| 先修关系 | 成员 1 维护实际课程数据；成员 3 校验环路并用于路径规划 |
| 推荐内容 | 成员 3 决定推荐对象和顺序；成员 1 提供资源和题目详情 |

## 8. 最终集成思路

### 8.1 保留四份成果

```text
个人成果
├── A13 教学考试系统冻结版
├── E12 成绩学档系统冻结版
└── F21 个性化推荐系统冻结版

团队成果
└── F13 AI 驱动的个性化学习平台集成版
```

成员 1、2 在第 7 天交付独立冻结版本。综合项目复制并接入这些版本，但不覆盖原始个人成果。

### 8.2 集成顺序

1. 在空数据库环境分别启动三个个人项目。
2. 统一运行端口、环境变量和健康检查。
3. 以成员 1 的用户系统签发统一 JWT。
4. 以成员 1 为课程目录主数据，向成员 2、3 同步只读快照。
5. 通过学习事件打通答题、成绩、错题、掌握度和推荐。
6. 增加 Platform BFF，对不一致接口做适配和聚合。
7. 新建统一 Vue 前端壳，迁移三个系统的核心页面。
8. 完成端到端测试、部署脚本和答辩材料。

### 8.3 不全面重构的原因

- 保留每名成员的独立成果和贡献证据。
- 避免个人报告与代码结构不一致。
- 防止第二周重新测试三个系统的全部业务。
- 将时间集中用于数据、事件和完整业务链，而不是重复开发 CRUD。

只有项目无法启动、跨系统 ID 混乱、关键接口缺失或核心逻辑无法复用时，才局部重构。普通字段差异优先在 BFF 或同步适配器中解决。

## 9. 两周计划

### 第一周：个人项目

**第 1 天**

- 冻结数据字典、ID、事件、API、端口和数据库名称。
- 三人完成数据库结构和跨系统字段确认。
- 成员 3 按契约准备 Mock 数据。

**第 2～3 天**

- 成员 1 完成课程、内容、题库和考试主流程。
- 成员 2 完成绩、档案、错题和统计主流程。
- 成员 3 完成数据导入、BKT、画像和掌握度页面。

**第 4～5 天**

- 成员 1 完成判分、幂等提交和事件接口。
- 成员 2 完成导入导出、事件接收和幂等处理。
- 成员 3 完成 DKT、混合推荐、路径规划和实验。
- 按统一接口样例进行第一轮契约验证。

**第 6～7 天**

- 补齐前端、异常处理、SQL、README、OpenAPI 和测试。
- 三个项目分别完成空库部署和个人演示。
- 成员 1、2 交付冻结版本。

### 第二周：综合项目

**第 8～9 天**

- 验收成员代码，完成空库启动。
- 建立统一 JWT、目录同步、事件游标和失败重试。

**第 10～11 天**

- 建立 BFF 和统一 Vue 前端。
- 打通“答题—成绩—错题—掌握度”链路。

**第 12 天**

- 打通“薄弱点—资源/习题推荐—学习路径—反馈”链路。
- 验证模型降级。

**第 13～14 天**

- 全流程测试、报告截图和团队合作报告。
- 从空数据库重新部署。
- 进行两轮答辩演练并冻结最终版本。

## 10. 最终验收故事线

1. 教师创建课程、章节、知识点和先修关系。
2. 教师上传资源、录入题目并发布考试。
3. 学生选课、学习并参加考试。
4. 教学考试服务自动判分并产生事件。
5. 成绩学档服务形成成绩、统计和错题本。
6. 个性化服务更新知识掌握度并识别薄弱点。
7. 系统推荐资源和习题，并显示推荐原因。
8. 系统生成带先修关系的学习路径。
9. 学生完成推荐内容后，掌握度和路径动态更新。
10. 教师查看班级成绩、薄弱知识分布和推荐效果。
11. 重复提交和重复同步不会产生重复数据。
12. 算法服务异常时自动降级或返回明确提示。

## 11. 共同交付标准

每个个人项目必须提供：

- 完整源代码
- `schema.sql` 和 `data.sql`
- `README.md` 和 `.env.example`
- OpenAPI/Swagger 文档
- Postman 测试集合
- 学生、教师、管理员测试账号
- 测试报告和演示数据
- 独立启动与空库初始化说明

最终综合项目另外提供：

- 统一启动脚本或 Docker Compose
- BFF、同步程序和统一前端
- 完整接口契约
- 团队合作报告
- 端到端测试报告
- 演示操作脚本和最终备份

## 12. 主要风险

| 风险 | 处理方式 |
|---|---|
| 字段和接口不一致 | 第 1 天冻结契约，差异通过适配器处理 |
| 项目只能在原作者电脑运行 | 要求 SQL、环境文件、README 和空库部署记录 |
| 公开模型无法用于新课程 | 公开数据用于实验；新课程使用 BKT 和课程内模型 |
| 三个前端无法合并 | 新建统一前端壳，只迁移业务页面 |
| 事件重复或丢失 | 使用事件 UUID、递增游标、幂等消费和失败重试 |
| 课程目录变化导致模型失效 | 模型绑定课程 ID 和目录版本 |
| 算法服务现场失败 | 预训练模型、本地文件和 BKT 降级 |
| 范围失控 | 两周只完成三门演示课程，十门课程后续扩展 |
