# 成员 1：教学考试系统开发与交接清单

对应题目：A13  
项目名称：基于 Spring Boot 与 Vue 的在线教育与考试管理平台  
冻结交付时间：第 7 天

## 1. 项目目标

独立完成一个包含课程教学、学习内容、题库和在线考试的完整系统；在综合平台中作为统一身份、课程目录、题目资源、原始答题记录和学习行为事件的主数据服务。

个人项目必须能够在不启动成员 2、3 项目的情况下独立运行和演示。

## 2. 数据所有权

成员 1 唯一负责：

- 用户、角色和登录身份
- 课程、章节、知识点目录
- 知识点先修关系的实际课程数据
- 学生选课关系
- 学习资料
- 题目及题目知识点关系
- 试卷和考试
- 原始答题记录
- 考试提交和即时判分
- 原始学习行为事件

成员 1 不负责：

- 正式成绩修改、排名和复杂统计
- 错题本的复习状态和错题笔记
- 学生知识掌握度计算
- 资源、习题推荐和学习路径
- 修改 `record_db` 或 `recommender_db`

## 3. 必须完成的功能

### 3.1 用户和权限

- 学生、教师、管理员三种角色
- 用户登录及 JWT 签发
- 当前用户信息查询
- 学生只能参加自己可访问的考试
- 教师只能维护有权限的课程

### 3.2 课程教学

- 课程增删改查和状态管理
- 多级章节及排序
- 知识点及难度
- 知识点先修关系维护
- 先修关系有向环检测
- 学生选课
- 课程目录版本 `catalog_version`

### 3.3 资源和题库

- 学习资源增删改查
- 资源与知识点多对多关联
- 题目增删改查
- 题目与知识点多对多关联
- 至少支持单选、多选和判断题
- 题目和资源状态管理

### 3.4 试卷和考试

- 组卷和题目分值
- 考试发布、开始和结束
- 学生创建考试作答实例
- 答案保存和提交
- 客观题自动判分
- 考试提交幂等
- 考试结果查询

### 3.5 学习记录和事件

- 查看资源产生学习行为
- 完成资源产生学习行为
- 题目作答产生答题事件
- 考试提交产生考试事件
- 提供按递增游标查询事件的接口
- 已生成事件不可修改或删除

## 4. 数据库交付

必须提供：

```text
teaching_db/schema.sql
teaching_db/data.sql
```

至少包含以下表：

```text
sys_user
course
chapter
course_enrollment
knowledge_point
knowledge_prerequisite
resource
resource_knowledge
question
question_knowledge
exam
exam_question
exam_attempt
answer_record
learning_event
event_knowledge
idempotency_record
```

必须实现的约束：

- `sys_user.username` 唯一
- `course.course_code` 唯一
- `knowledge_point(course_id, knowledge_code)` 唯一
- `question(course_id, question_code)` 唯一
- `course_enrollment(course_id, user_id)` 唯一
- `exam_attempt(exam_id, user_id, attempt_no)` 唯一
- `learning_event.event_id` 唯一
- `learning_event.event_seq` 自增且唯一
- 先修知识点不能指向自身
- 考试实例使用 `version` 做并发控制

所有需要跨系统使用的主键必须为 UUID，并严格遵守《02-统一数据与接口契约》。

## 5. 必须提供的 API

统一前缀：`/api/v1`

```text
POST /auth/login
GET  /users/me
GET  /courses
GET  /courses/{courseId}/structure
GET  /resources?courseId=&updatedAfter=&page=&pageSize=
GET  /questions?courseId=&updatedAfter=&page=&pageSize=
GET  /students/{userId}/enrollments
GET  /integration/events?afterSeq=&limit=
GET  /exams/{examId}
POST /exams/{examId}/attempts
POST /attempts/{attemptId}/submit
GET  /attempts/{attemptId}/result
```

`/courses/{courseId}/structure` 一次返回课程、章节、知识点、先修边和 `catalogVersion`。

每个接口的 OpenAPI 文档必须说明：

- 请求方法和 URL
- 参数名称、类型和是否必填
- 权限要求
- 分页方式
- 成功响应
- 错误码
- 请求和响应示例
- 是否支持幂等

## 6. 考试提交幂等

```http
POST /api/v1/attempts/{attemptId}/submit
Idempotency-Key: uuid
```

处理规则：

1. 首次提交时锁定考试实例。
2. 保存答案和判分结果。
3. 生成答题及考试事件。
4. 保存幂等键和响应摘要。
5. 再次提交相同幂等键时返回第一次结果。
6. 不重复判分，不重复生成事件。

## 7. 事件要求

必须生成：

```text
COURSE_ENROLLED
RESOURCE_VIEWED
RESOURCE_COMPLETED
QUESTION_ANSWERED
EXAM_SUBMITTED
```

`QUESTION_ANSWERED` 至少包含：

```text
eventId
eventSeq
userId
courseId
questionId/objectId
correct
score
durationMs
occurredAt
knowledgeItems
attemptNo
traceId
```

`EXAM_SUBMITTED` 至少包含：

```text
eventId
eventSeq
userId
courseId
examId
attemptId
score
occurredAt
traceId
```

事件查询必须满足：

- 按 `eventSeq` 升序返回。
- 支持 `afterSeq` 和 `limit`。
- 每次最多返回 500 条。
- 重复查询同一游标时事件内容保持不变。

## 9. 个人项目验收流程

1. 在空数据库中执行 `schema.sql` 和 `data.sql`。
2. 启动后端和前端。
3. 管理员、教师、学生分别登录。
4. 教师创建课程、章节和知识点。
5. 教师维护先修关系并验证环检测。
6. 教师上传资源、录入题目并关联知识点。
7. 教师创建试卷并发布考试。
8. 学生选课、学习资源并完成考试。
9. 系统自动判分并返回考试结果。
10. 查询新增学习事件。
11. 重复提交同一考试，确认不重复判分。
12. 重复查询事件，确认事件内容不变化。
