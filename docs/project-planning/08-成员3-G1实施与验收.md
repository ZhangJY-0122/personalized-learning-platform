# 成员3 · G1 实施与验收记录

后续进展：G2本地作答与学习状态闭环已完成并验收；最新进展见 [09-成员3-G2实施与验收.md](09-成员3-G2实施与验收.md)。本文保留G1历史边界与证据。

## 1. 交付边界

本次“第一阶段”按开发前约定的 G1 执行：空库可启动、本地账号可登录、课程及资源可独立打开。它是 M0 的第一道关卡，不代表整个 M0 或完整推荐系统已经完成。

已实现代码：

- Vue 真实页面：登录、课程列表、章节/知识点目录、本地资源正文、题干与选项浏览、退出；包含加载、错误、空授权状态与手机布局。
- Spring Boot：登录、当前账号、退出、本人/管理员查选课、按权限查课程、结构、资源列表/正文、题目列表/详情。
- MySQL + Flyway：V1 正式基础表、V2 演示账号、V3 演示目录；保留既有开发卷和历史 prep_catalog。
- 认证：BCrypt cost=12；随机本机密钥签发 HS256 JWT；校验签名、issuer、audience、过期、账号启用状态与角色；退出撤销写入数据库，重启不解除撤销。
- 授权：学生按选课、教师按课程授权、管理员查看本地目录；后端逐对象校验，不以隐藏前端按钮替代权限；已停用课程和下架资源不公开。
- 题目安全：接口显式选择安全字段，所有角色都不返回 answer_json；资源正文以纯文本渲染，不执行 HTML。
- 工程：构建运行 Java 测试，Maven 缓存仅拉取实际依赖；OpenAPI 区分 G1 与 PLANNED。

验收中实际发现并修复：数据库与后端同时重启时，后端可能在数据库就绪前连接失败并退出。已配置 Flyway 连接重试（20次、最大间隔2秒）与容器 unless-stopped 恢复策略；修复后重新创建空卷并完成重启验收。代理同时改用 Docker DNS 动态解析，后端容器替换后仍能经网页端访问资源。

首次失败验收的临时容器/网络已移除，卷 f21-g1-check-0e35d031_f21-data 保留；最终成功验收的临时容器/网络已移除，卷 f21-g1-check-656f346f_f21-data 保留。主开发项目 f21-preflight 持续运行，未清空其数据卷。

非阻塞提示：当前 Flyway 11.7.2 对 MySQL 8.4 输出支持版本警告。本机迁移、校验和重启实测通过，但不据此承诺所有版本兼容；升级前须重新跑本关卡，不通过降级现有MySQL数据卷消除提示。该提示有[上游问题记录](https://github.com/flyway/flyway/issues/4168)。V3部分浮点难度文字被 DECIMAL(4,3) 舍入；已查库确认知识点难度为0.200/0.270/0.340/0.410/0.480/0.550/0.620/0.690，与预期一致。已应用V3不改写；后续生成器显式固定3位小数。

代理实现依据 [Nginx proxy_pass 文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)，使用变量目标配合 resolver；验收包含后端容器替换后再次读取资源。

## 4. 使用与维护

在 f21-personalized-learning 执行 bash scripts/start.sh。首次需要 Docker、Python3 和构建网络；生成并保留私有 .env。页面 http://127.0.0.1:15173；健康接口 http://127.0.0.1:18083/api/v1/health。

停止用 docker compose stop；正常重启不清空命名卷。严禁为解决迁移错误直接删除现有卷。独立验收脚本仅移除自己创建的测试容器及网络，保留测试卷，便于追溯。

已应用的迁移不再修改。后续用增量版本追加；开发库 baseline-version=0 仅兼容原 prep_catalog，不可用于接管任意非空数据库。MySQL DDL 中途失败可能留下部分结构，需要人工检查和备份后恢复，不自动 repair。

| JWT存储及撤销规模 | 中 | sessionStorage只限当前标签页；仍需防XSS，关标签页不等于服务端退出；当前撤销记录不自动清理，规模化前增加过期清理 |
| 数据库迁移失败与误删卷 | 中 | Flyway校验、保留旧数据、独立空库验收；禁止自动清库修复，生产备份恢复需另验 |
