## 4. 已知 P0/P1 问题与冻结解决方向

### 4.1 P0：资源路径完成证据外键类型错误

当前流程：

1. `RecommendationService.resourceActivity` 向 `resource_activity` 插入 `event_id`。
2. 它把该 ID 传给 `LearningPathService.completeResourceNode`。
3. 路径服务尝试写入 `learning_path_node.source_event_id`。
4. V6 把该字段外键指向 `event_consume_log(event_id)`。
5. 资源行为 ID 不存在于 `event_consume_log`，因此 MySQL 拒绝更新并返回 500。

冻结方向：使用 V7 区分题目事件和资源行为来源，不得通过伪造一条 `event_consume_log`、关闭外键检查或删除外键来掩盖问题。

推荐数据模型：

- 保留 `learning_path_node.source_event_id`，仅表示题目/学习事件，继续外键到 `event_consume_log(event_id)`。
- 新增 `learning_path_node.source_resource_activity_id`，仅表示资源完成，外键到 `resource_activity(event_id)`。
- 两个来源字段分别唯一。
- 普通完成节点最多有一个直接来源。
- 继承完成节点使用 `carried_from_node_id`，不复制原始事件 ID。
- API 的既有 `sourceEventId` 可继续返回统一来源 ID，但服务端映射必须按 `item_type` 选择对应列；如要新增 `sourceType`，先更新 OpenAPI、fixture 和决策文档再改实现。

必须验证：

- `VIEWED` 只把节点置为 `IN_PROGRESS`，不填写完成来源。
- `COMPLETED` 写入 `source_resource_activity_id`，节点完成但 BKT 不变。
- 题目事务 B 成功后写 `source_event_id`。
- 资源完成事务任何一步失败时，`resource_activity`、节点、revision 和幂等记录全部回滚。
- 同幂等键重试返回同一来源 ID，不重复推进节点。
- 不同幂等键重复完成同一节点返回冲突，不产生第二条完成证据。

### 4.2 P0：目录发布失败可能留下半更新

当前 `CatalogImportService.importCatalog` 在一个 `TransactionTemplate` 内调用 `publish`，随后在同一事务回调中捕获 `RuntimeException` 并返回失败结果。异常被内部消费后，事务可能提交 `publish` 已经写入的前半部分。

冻结方向：导入作业审计与目录发布事务分离。

推荐流程：

1. 规范化请求并计算内容 hash。
2. 在短事务中创建或读取幂等 `import_job`。
3. 在发布事务开始前执行所有不依赖写入的结构验证。
4. 在一个独立事务中锁定课程并写完整 snapshot/canonical/mapping/rebuild job。
5. `publish` 内任何异常必须继续向外抛出，使发布事务整体回滚。
6. 发布事务回滚后，在另一个短事务中更新 `import_job=VALIDATION_FAILED/FAILED` 并保存 `import_error`。
7. 只有发布事务提交成功后，才把作业改为 `SUCCEEDED`。

不能采用：

- 在失败后逐表手工删除“看起来已经写入”的行。
- 关闭 autocommit/外键后不恢复。
- 修改当前课程版本后再尝试补救。
- 失败时删除整个测试数据库来宣称原子性。

必须通过触发器或受控 SQL 故障证明：

- `catalog_snapshot` 写入中途失败：新版本无任何残留。
- canonical 表更新中途失败：旧课程版本、旧资源和旧题目完全不变。
- mapping 写入失败：新目录不发布。
- rebuild job 创建失败：课程仍停留旧版本。
- 作业失败状态和逐项错误仍可查询。

### 4.4 P1：题目快照没有独立排序字段

当前 `question_snapshot` 不保存 `sort_order`。临时改为从当前 `question` 表读取会导致历史目录的路径生成依赖可变 canonical 数据。

冻结方向：V7 为 `question_snapshot` 增加 `sort_order`。

迁移要求：

- 先新增可空列。
- 当前激活目录可从 `question` 表按相同课程、版本和题目 ID 回填。
- 已经通过导入作业保存的历史版本，优先从 `import_job.request_json` 中的原始 `questions[].sortOrder` 回填。
- 回填后运行断言，确认所有可用于路径生成的题目快照均非空。
- 只有断言成立后才改为 `NOT NULL`。
- `CatalogImportService` 新写快照时必须直接写入请求中的 `sortOrder`。
- `LearningPathService` 只能读取 `question_snapshot.sort_order`，不得读取当前 `question.sort_order` 作为历史快照排序。

如果无法无歧义回填某个历史快照，不得猜测；应把该目录标记为不可用于路径生成并输出明确错误，再由管理员重新导入完整历史目录。

### 4.5 P1：事件导入状态永远是警告

当前实现无论 `failed` 是否为空都返回 `SUCCEEDED_WITH_WARNINGS`。

冻结状态规则：

- 全部新事件或合法重复事件成功：`SUCCEEDED`。
- 至少一项失败、其余项成功/重复：`SUCCEEDED_WITH_WARNINGS`。
- 整个请求在批次级校验前失败：HTTP 400，不创建成功作业；若已创建审计作业，应为 `VALIDATION_FAILED`。
- 数据库/系统故障导致无法可靠完成：`FAILED`，可按冻结策略重试。
- `success_count`、`failure_count`、accepted、duplicate、failed 三类数量必须可对账。

### 4.6 P1：CSV 解析不是可靠 CSV

当前 `split(",")` 无法处理引号、引号内逗号、转义双引号和常见换行规则。

冻结方向：

- 优先引入锁定版本的成熟 CSV 解析库，例如 Apache Commons CSV；不要继续扩展手写 split。
- 新依赖写入 `pom.xml`，由 Maven 锁定解析，不做全局安装。
- 明确 UTF-8、首行表头、允许/拒绝的空行、列名、最大 10 MiB、最多 10000 数据行。
- CSV 只负责解析成与 JSON batch 相同的规范事件对象，后续验证、hash、幂等和入队必须复用同一逻辑。
- CSV 作业类型必须准确记录为 `EVENT_CSV`，不能全部伪装为 `EVENT_JSON`。

### 4.7 P1：主文档与真实状态不一致

当前 README 仍写“学习路径未实现”“健康阶段为 G2”，G4 记录仍写本机没有 JDK/Maven/Compose。这些内容只有在真实验收完成后统一修正。

4. 为 `question_snapshot` 增加 `sort_order`。
5. 安全回填现有快照排序。
6. 为后续快照写入建立非空约束或等价数据库保证。
7. 不重写任何历史学习事件、BKT、推荐或路径完成事实。

### 5.3 V7 迁移测试

必须覆盖三个场景：

#### A. 全新空库 V1→V7

- 启动全新隔离卷。
- Flyway history 必须正好包含 1～7 且全部 success=1。
- 默认课程、资源、题目和账号数量与既有基线一致。
- 新字段、索引、外键和约束存在。
- 能生成路径并完成资源节点。

#### B. 已有 V6→V7

- 使用隔离 V6 基线，不使用主开发卷。
- 预先生成 ACTIVE/COMPLETED/INVALIDATED 路径和资源行为。
- 升级后旧路径、节点、事件、推荐和 BKT 行数及关键 hash 不变。
- 当前目录题目排序完成回填。
- 原有题目来源仍可追溯。

#### C. V5→V7 原地升级

- 使用测试专用 Compose 配置先把 Flyway target 设为 5。
- 在 V5 状态写入 G1/G2/G3 基线数据。
- 停止旧服务，不删卷。
- 取消 target 限制，用当前服务启动并迁移到 V7。
- 重新运行 G1/G2/G3 关键查询和 API。
- 验证旧推荐、反馈、资源行为和 BKT 均未丢失。

如应用在 target=5 时因 G4 Bean 查询新表而无法启动，应增加测试专用配置关闭 G4 worker，而不是伪造 Flyway history 或手工标记迁移成功。

### 5.4 V7 迁移停线条件

出现以下任一情况立即停止：

- V1～V6 checksum 改变。
- 升级后历史行数减少。
- 现有路径来源被置空或指向错误表。
- 无法解释的 `sort_order` 被随意填充。
- 迁移需要关闭全局外键检查。
- 迁移失败后继续让应用提供写服务。

## 9. 安全与数据保护要求

- `.env` 不提交。
- JWT secret、数据库密码、Token 不写入 JSON、截图或日志产物。
- API 错误响应不返回堆栈、SQL 或底层表名。
- 服务端日志保留 traceId、异常类型、message 和堆栈，便于本地诊断。
- 导入文件限制大小和行数，拒绝超限后不得产生业务数据。
- 文件内容按 UTF-8 处理，拒绝无法解析内容。
- 不信任客户端提供的 userId、correct、trusted、stateRevision。
- 路径和推荐归因互斥由服务端验证。
- 管理员导入不能冒用本地可信练习来源。
- 测试账号和演示密码只能用于本机隔离环境。
- 不把 MySQL 3306 映射到公网或局域网接口。
- Web/server 继续只绑定 127.0.0.1。
