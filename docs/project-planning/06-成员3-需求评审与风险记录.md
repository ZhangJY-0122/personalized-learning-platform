# 成员3：需求评审与风险记录

日期：2026-09-09  
评审对象：05文档V1.1  
输出基线：05文档V2.0独立交付版  
范围依据：用户要求先独立完成F21，数据与背景自行Mock/模拟，不等待其他成员。

## 1. 评审结论

结论为“独立开发可行，按阶段有条件通过设计评审”。已有文档规定了主要功能，但在来源、算法语义、恢复流程和验收口径上存在会导致实现返工的缺口。

本次将可确定的问题直接修订到05文档，保留原稿以便追溯。设计修订不代表实现和测试完成；目前没有执行应用启动、训练或性能测试，也没有证据可以承诺一周完成全部研究成果。

原方案依赖其他成员的部分根据用户最新要求改为本地身份、课程包、资源和练习。统一契约及其他成员文档无需为本项目启动而修改。

## 5. 残余风险与接受条件

- 工期：可减少M2范围，不能默认省略M1实验。G4通过只可宣称核心版完成；G7才是完整独立研究成果。
- 数据获取：不影响自带数据运行；公开实验完成状态必须由真实数据清单、指标和产物证明。
- 算法效果：允许DKT不领先；只要求实现与评估正确，不保证AUC或NDCG优于基线。
- 合成数据外推：只能支持流程与机制验证，不支持真实学生教学收益结论。
- 工程可靠性：事务、重建和降级在设计层面闭合，但未执行代码测试，风险仍未实证关闭。

无需等待其他成员批准任何本地实现选择。未来需要外部平台对接时，单独评审身份、ID来源、事件游标和目录同步，不影响本轮交付。
